# 予約一覧フロントエンド

React + Vite（JavaScript）。別のターミナルで既存のSpring Boot APIを起動してください。
Docker・SQLの操作やDB変更は不要です。

リポジトリのルートから：

```sh
cd frontend
npm install
npm run dev
```

ブラウザで http://localhost:5173 を開いてください。
APIのCORS設定はこのオリジンだけを許可しています。
5173番ポートが使用中の場合は自動で別ポートに切り替えず、エラーで停止します。

- 起動時：`GET http://localhost:8080/api/reservations`
- 検索：`keyword` と `rentalDate` を指定して再取得（空欄は省略）
- 日本語は `URL.searchParams` でエンコード
- クリア：入力欄を空にしてパラメータなしで全件を再取得
- null・空文字は `-`、利用人数は `users.length`、金額は `¥` と桁区切りで表示
- 「受付時間」列には既存APIの `pickupTime` を表示
- 読み込み中・0件・取得失敗を表示

```sh
npm run build
```

本番向けビルドを確認できます。APIはローカルの8080番を直接参照する開発用構成です。

## 追加品目の画面確認（Phase 5）

最新バックエンドを起動し、個別料金マスタと追加品目テーブルの追加SQLを適用してください。

1. 当日受付でメイン品目・日数を選び、小物チップを複数選択して登録します。
   チップは利用者の区分に合う `additionalPriceMasterIds` と、表示用 `smallItems` の両方に保存します。
   自由入力は `smallItems` のメモだけに保存し、料金には含めません。
2. 詳細の利用者ごとの内訳で、メイン・各追加品目・利用者合計（税込）を確認します。
3. 追加品目をチェックで付け替え、日数を変更すると見込み金額が変わります。
   追加品目のチェックは個別8品目だけを表示します。メイン品目の候補には個別8品目を表示せず、既存のOR行は保持します。
4. 「変更を保存」でPATCHし、保存済みの確定金額を確認します。
   一覧に戻って詳細を開き直しても選択と金額が保持されます。
   全チェックを外して保存すると追加品目を解除します。

小物メモは受付時の記録として保持されます。現在の料金対象は内訳・チェック欄で確認してください。
