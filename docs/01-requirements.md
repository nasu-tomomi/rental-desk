# Rental Desk 要件定義

## 概要

スキー・スノーボードレンタル店の予約・受付・貸出・返却を、紙の管理からデジタル化する受付管理アプリ。
1番の目的は、朝の受付が混み合う時間帯に、お客様の待ち時間を短縮し、スムーズにレンタル引渡しスタッフに流せるようにすること。

## 現行業務と課題

現行の業務フローは次のとおり。

- ネット予約は予約メールを印刷して紙で管理する
- 当日来店のお客様は、紙の申込書に手書きで記入する
- 貸出時は紙の控えを渡し、返却時は控えと照合する
- 繁忙期は1日に100組近い予約がある

課題：

- 「誰が来店済みで、誰がまだ返却していないか」が一目で分からない
- 紙の申込書には料金が印刷されておらず、スタッフが料金を暗記し、電卓で計算して会計している
- お客様の約9割が海外の方で、連絡手段は電話だけでは不十分（LINE／WhatsAppが必要）

## 目指す受付フロー（来店〜貸出）

1. スタッフが「本日の予約一覧」を開く（その日の予約が全部見える）
2. お客様の名前・フリガナで検索し、すぐ予約が見つかる
3. 予約内容（レンタル品・人数など）を確認する
4. ボタン1つでステータスを「貸出中」に変更する
5. 返却時はボタン1つで「返却済」に変更する

## 機能要件（MVP）

- 予約の登録・一覧表示・削除
- 本日の予約一覧の表示
- 名前・フリガナでの検索（ローマ字にも対応）
- ステータス管理（予約済 → 貸出中 → 返却済、予約単位）
- 料金の自動計算（料金マスタを参照）
- 当日来店のお客様の簡易登録（名前・電話・品目・人数のみ）

## 将来拡張（MVPには含めない）

- 支払い状況の管理
- CSV取込（ネット予約の一括取り込み）
- QRコードによる備品管理
- WordPress予約システムとの連携

## 料金計算のルール

- 料金は「品目 × 区分（おとな／こども）× 日数」で決まる
- 日数の料金パターンは3つだけ：1日料金／2日料金／3日目以降は1日ごとの加算
  - 計算式：1日＝1日料金、2日＝2日料金、3日以上＝2日料金＋（日数−2）×3日目以降料金
- カテゴリはスタンダード、BURTON 2027、ハイグレードの3種
- こども料金は小学生以下が対象。返却時間は17:00
- 料金データは料金マスタ（docs/03-prices.csv）に持つ

## 設計の前提（元の業務資料から）

- 予約1件＝「申込者1人＋利用者1〜複数人（最大20人ほど）」。利用者ごとにレンタル内容とサイズが違うため、予約と利用者は別のテーブルに分ける（詳細は設計メモ docs/02-er-diagram.md）
- 受付一覧で必要なのは、受取店舗・レンタル日時・申込者名（フリガナ）・電話・利用者数・レンタル内容・スキー場・支払い方法・ステータス。住所やメールは一覧に出さない
- 紙の申込書にある「返却日時」と「実際に貸したサイズのメモ」は、アプリにも項目として持つ

## 技術構成

- バックエンド：Java / Spring Boot（REST API）
- フロントエンド：React
- データベース：MySQL（Dockerで起動）
- リポジトリ構成：1つのリポジトリに backend / frontend フォルダを分ける
